# I-B17 — R-STORE-106 artifacts objects through internal/store; settings leaf mask paths

## Done
- internal/store/objects.go (new): `store.Objects` over the artifacts bucket = the former
  internal/cache/objects.go moved unchanged (same s3client, same retry/lost-response logic, same
  requests): Get (Range, If-Match), Read (bounded), Head, Put (If-None-Match / If-Match), PutFile,
  CreateFile (streaming, If-None-Match), Copy (CopySourceIfMatch + dst condition), Delete.
  Errors `store.ErrObjectNotFound` (distinct from the record `ErrNotFound`), `ErrPrecondition`,
  `ErrRange`, `ErrTooLarge`. Lifecycle rule and the LISTs stay in internal/store/sweep.
- internal/cache/objects.go: type aliases (`cache.Objects = store.Objects`, Object, Info, Cond),
  error vars = the store sentinels, `cache.OpenObjects` calls `store.OpenObjects`. No caller
  changed (internal/promote, worker, build, overview, cmd/bob-server keep their code), so request
  budgets and the promotion/streaming paths are byte-for-byte the same code.
- internal/orchestrator/controllers_staging.go: `Staged{Objects *store.Objects}` deletes by known
  key through `Objects.Delete` (was `S3 *s3.Client` + DeleteObject; type had no users).
- tools/lint/dbusage.go: S3 SDK allow list = internal/store (incl. sweep, s3client) and
  internal/logstore (lake requires an *s3.Client; SPEC R-STORE-106 lake exception, the protected
  test allows it too). Lint testdata internal/cache/c.go and internal/worker/w.go now expect the
  import diagnostic (stricter rule; protected tool area, reported by CI per D68).
- docs/dynamitedb-lake-usage.md guardrail text updated.
- internal/overview/settings.go: UpdateSettings accepts every leaf of retention/sessions
  (`retention.cache_unreferenced_days`, `sessions.cli_idle_days`, ... in proto or protojson
  camelCase form) besides the groups and top-level fields; etag and unknown paths are refused.
  Fixed a nil-interface call (`cur.CLIIdleDays.Value()` on a record written without sessions).

## DECISIONS
- D-IB17-1 cache aliases instead of rewriting every caller: callers and cmd/ (not owned) keep
  compiling unchanged; the only S3 code is in internal/store.
- D-IB17-2 `retention.cache_unreferenced_days = 0` through its leaf path is an explicit "0 days"
  (R-STORE-150 acceptance), stored as a separate flag `CacheNow` (cbor `rz`) because a fetched
  dynamitedb record cannot tell absent from 0. The whole `retention` group keeps "0 = default"
  (a client that omits the field must not make GC collect everything unreferenced at once).
