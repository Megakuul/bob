## DECISIONS
- A280 bob status decides fresh/stale without planning: materialise records an inputs digest per
  root in the manifest (`inputs`, plus the root's `keep` names; both omitempty additions to the
  §03.6.6 schema, like the existing `link`). Digest = bob version + for a codegen package its
  closure's (kind, label, spec, nixpkgs attr, source store path computed like the sources stage)
  and the nixpkgs pin; for other roots (npm node_modules) its own declaration and bob.lock's bytes.
  Positions are left out. Planning was not an option: it builds codegen (two-phase cutoff) and Go
  cutoff units, and costs 7-30 s warm against the 0.3 s budget.
- A281 bob status only reads (no lock, no gen, no network; only the evaluator's Go may be fetched
  as for bob check) and exits 0 whatever the states are; `bob gen --check` stays the gate.
- A282 States: edited (a file not bob's: edited, foreign, tracked) > stale (pending entries or temp
  files of an interrupted write, or inputs differ/unknown) > missing (dir or recorded files gone;
  also a defined codegen package without a root, shown with dir "-") > fresh; orphan = a root whose
  label is no package of the graph. Lock freshness = bob check's offline lock findings (1012).
- A283 A node_modules symlink that points at the same store object through another bob home
  (`…/nix/store/<hash-name>/…`) is rewritten, not a conflict (manifest loss after the state home
  moved, R-FW-066 (e)); identical regular files were already adopted.
- A284 bob dev: `--servers-only --no-servers` is a watch-only session (no shell, no servers) until
  a signal; with a command it is still a usage error. The codegen watch regenerates stale/missing
  codegen roots on entry and on changes (stat poll 250 ms of the known inputs, full check every 2 s),
  with build.Run(CmdGen) for those labels only (native files do not depend on codegen inputs).
  SPEC says inotify; polling the known files keeps it simple and cheap (~5 % CPU idle).
- A285 Test correction 70 (T5): RFW067 gopls shim at the project root, per SPEC §02.7.2/§02.7.3.
- A286 Examples are compile-checked and verified by evaluation in a scratch repo, without Output.
- A287 npm lock/gen at the 5-min harness timeout: no hang, no code change (see above).
