## DECISIONS (A500+)
- A500 The toolchain struct of nixext is `ToolchainAttrs`; `nixext.Toolchain(p)` keeps the name
  SPEC/ADR use (Go forbids a type and a function both named Toolchain).
- A501 Handles are `var X = nixext.New("attr")`: New is a plain inlinable composite literal, so
  the compiler initialises all 22 427 handles statically (no init code) and the linker drops the
  unused ones (B-103 measured 184 bytes unstripped / 0 stripped). Attr stays sealed.
- A502 meta.mainProgram defaults are one generated string constant (`"\n<attr>\t<prog>"` lines,
  307 KiB) instead of a map: no init cost; linked only when Exe is used (+263 KiB then).
- A503 Doc comment shape: a missing version is written `unversioned`, a missing description
  `<attr> <version>`, licence `unknown`; descriptions cut at 160 bytes on a word boundary with
  "…" (keeps TestRNIX031's one-line `Name is attr ver: … Licence: …` shape).
- A504 GoName extras: `+` → `Plus` (attribute grammar allows it); empty parts are dropped;
  reserved names also include Name, Out*, Outputs etc. (fallback A_<attr>).
- A505 Snapshot includes `failed` (attribute itself throws) and `evalOk` (drvPath evaluates with
  allowUnfree): both exclusion class eval-failure; availability = lib.meta.availableOn for the two
  Linux systems; alias = missing with allowAliases=false.
- A506 The online snapshot step is behind `-tags online`; gen and -check import neither the
  network, the store nor cgo (they read lock.DefaultRev from the source file). TestRNIX031 runs
  `go run ./cmd/nixpkgsgen -check` without CGO_ENABLED, which fails on hosts without gcc when
  net/os/user are linked.
- A507 Budget benches B-098…B-103 in tools/budgetbench (group nixpkgs).
- A508 BOB-E-1028 positions are the package's definedAt (not the Glob call): no IR schema change
  for source positions; the pattern text is the raw user pattern (fault 82/83/91 wording).
- A509 Slot errors: Get of an unbound slot is reported where Get runs; Bind twice at init time
  (early diagnostic); NewSlot/Bind outside a package-level var → the R-FW-011 wording with
  `bob.NewSlot` / `Bind`.
- A510 Unit counting is per (bob.go dir, ecosystem) of the main module only; dependency repos are
  not checked. Kind word in 1029 = kind name after the last '.'.
- A511 1001 `pin` variant: used when the pinned revision lacks a top-level attribute and the pin
  is not lock.DefaultRev (or the bobtest hook says so); nested/computed attributes keep the plain
  1001 with suggestions.
- A512 Default pin: PinNixpkgs pins DefaultRev for the default channel unless updating or the old
  pin of the same channel is kept; the transient pin of a lockless build of the default channel
  never asks the channel head.
- A513 Column of a typed handle call: qualifier chains (`nixpkgs.Openssl.Lib`) start at the first
  identifier; of several calls on one line, the one whose handle folds to the attribute wins.
- A514 Docs quickstarts that `bob init` writes show the second bob.go as a plain block (bob init
  writes it; TestSnippetsTypeCheck's module inference needs a subdirectory import); pages that
  write their files use per-directory file= blocks (outputs: slot in deploy/bob.go, labels
  //deploy:hello-*).
- A515 OCaml template/quickstart: library moved to greet/ (one OCaml unit per package).
- A516 `bob version` does not print the surface revision yet (pkg/cli not mine): status page
  says so; NEEDS below.
- A517 Typed-surface compile errors and slot errors are coded BOB-E-1020 errors of their own
  (`<pos>: invalid nixpkgs package: undefined: nixpkgs.Opensll`, `<pos>: invalid slot: …`) with
  a hint argument; the evaluator's `bob::` diagnostic line gains optional `col` and `hint`
  fields (pkg/bob → pkg/engine/ir/evalout.go, bounded), so 1029/1020 carry file:line:col.
- A518 A node's IR column is the column of the constructor the bob.go called to create it
