## DECISIONS
- D-IB12-1 Project ids are `^[a-z]([a-z0-9-]{0,38}[a-z0-9])?$` (1–40 chars, letter first), not the 3-char-minimum
  slug of §6.1: the suites' p1/p2 and RBAC bindings (D-IB5-7) use 2-char ids; same choice as D-IB4-1 for SAs.
- D-IB12-2 A project may have no repository (forge_integration_id and repo_full_name both empty): remote/upload
  builds only (R-PIPE-009). One without the other is InvalidArgument.
- D-IB12-3 No `pname/` record: the project id is the URL name (`/p/<project>`), so proj/<id> create-only gives
  uniqueness; display names need not be unique.
- D-IB12-4 The projects index entries carry the list fields (display name, repo, health, …) so ListProjects reads
  only pidxm + pages (§05.5.2 "1 + pages"). Pending entries implement intent-first without phantoms: creates,
  deletes and repair write Pending first; Repair settles entries older than 5 min in the index-repair pass. The
  listed link health is the stored one; GetProject adds the integration's AUTH_FAILED.
- D-IB12-5 The pipelines cache ppl/<project> is written by two build-controller hooks: Evaluated (definitions of
  the newest default-branch evaluation — any newer build while no default-branch evaluation exists — plus the
  matched pipelines' last build "running") and Finished (final state per pipeline run). defined_at stays empty:
  the evaluation report carries no source positions for pipelines.
- D-IB12-6 GetOverview filters builds by the caller's BuildService/ListBuilds scope (the overview lists builds);
  RecentFailures and ListProjects use their own method's scope (LIST_FILTERED). Worker counts are cached 30 s and
  queue heads 10 s per orchestrator so a warm overview stays at "3 + classes" requests.
- D-IB12-7 Settings live in one record set/server (the API's single etag covers all fields); the update mask
  takes top-level fields only (retention and sessions are replaced as a whole). Consumers still read their
  values from the environment (NEEDS).
- D-IB12-8 Data without a producer yet answers valid, empty results (PackageDurations rows, ListTopPackages,
  GetCacheStats counts, cache_hit_rate_24h 0) rather than 501, so the UI pages and R-API-151 work; requests are
  fully validated (days ≤ 400, limit ≤ 100).
- D-IB12-9 Release and registry: lists answer empty (no release or image can exist before M16.3/M16.4); every
  lookup or change stays 501 "not implemented: bob.release.v1.ReleaseService/<m>". DeleteProject does not check
  releases yet (R-STORE-007) — M16.4 adds the check.
- D-IB12-10 The devstack seed goes through the public API (CreateProject, CreateBuild with an uploaded snapshot,
  CancelBuild once the build has a job) plus a root-key PUT of the snapshot (no /upload endpoint yet). Only
  `tools/devstack up` seeds (default on, `-seed=false` to skip); stacks started with stack.Start directly
  (tests/store, tests/server) are unchanged.
