### A365 — R-NIX-007 "unchanged nodes are not recomputed": read side not implemented
The drv cache key (store.DrvKey, written by build.recordDrvCache) is sha256(canonical IR node +
the planned derivation's own InputDrvs + generator version + builder). It cannot be read to skip
planning, for two measured/structural reasons:
1. **Circular**: the input drv paths are those of the derivation being planned (d.InputDrvs);
   for ecosystem nodes they include derivations planned inside the same Plan call (Go package
   groups, std, npm tool drvs), so the key exists only after the work it should skip.
2. **Unsound with the specified key**: a node's derivation also depends on inputs that are not
   in the key: the imported source paths (inputSrcs: a bob.run's source tree, every Go
   package's source tree) and the files the Go planner reads from the working tree (go/build of
   workspace packages, go.mod). Editing a .go file changes neither the IR node nor any input drv
   path of a Go binary's IR deps, so a hit would return the old derivation (stale build: AGENTS
   §2.1). Even for bob.run the source path is an inputSrc, not an input drv.
The R-NIX-007 acceptance (second build imports 0 drvs) holds already (ImportDrvsAt checks
validity by path, A315). What the rule wants (no recomputation of what cannot have changed) is
implemented here for the inputs that provably cannot change: store paths (A360, A361). Making
the drv cache readable would need a key that covers every input of a node's planning (source
paths, files read), i.e. a SPEC change of R-NIX-007's key: owner question, raised in the report,
not decided here.
