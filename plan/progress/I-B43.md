## What changed
1. **Package lists of vendored module trees cached per tree (A360)** `treePackages`: the list
   `GeneratorModuleOf` needs for gqlgen's vendor/ (modulePackages walk of every third-party
   tree, 87 trees on fixture codegen, ~46 ms CPU per no-op) is cached in
   `$XDG_CACHE_HOME/bob/go-packages/<sha256(host path)>`. Only store paths (host path ends with
   the /nix/store path) are cached: module trees are content-addressed by the lock's tree hash.
   Entry = version line, module path, strictly sorted import paths within the module; anything
   else is a miss and recomputed. Written atomically (temp + rename), failures ignored.
2. **go/build reads of store-path package directories cached (A361)** `importDir(..., inStore)`:
   136 of 144 ImportDir calls of a codegen no-op read module trees or content-addressed codegen
   output (refThird/refGen), ~55 ms CPU. Cached in `$XDG_CACHE_HOME/bob/go-build/<sha256(key)>`,
   key = cache version, Go version bob is built with, ImportComment mode, every build.Context
   field goContext does not fix plus the ones it does, and the host directory. Store-path
   packages are always slimmed to the fields the planner reads (`slimPackage`: Dir, Name,
   ImportPath, the file lists, cgo CFLAGS/LDFLAGS/pkg-config, imports, embed patterns), cached
   or not, so the planner sees the same package either way; an entry is written only when it
   JSON-decodes back DeepEqual (invalid UTF-8 file names are never cached). Workspace
   directories are never cached.
3. **resolve without string building (A362)**: `within(ip, mp)` instead of
   `HasPrefix(ip, mp+"/")`, and `thirdOf` walks the import path's prefixes (longest first)
   against a per-main map of selected package-providing modules instead of scanning the whole
   build list with `mp+"@"+v` per import (~45 ms -> ~3 ms). Equivalence test TestThirdOf
   against the old scan.
4. **go section decoded once per command (A363)** `readGoSection`: single-entry memo
   (bytes.Equal on the raw section) for the read-only decodes in lockModules, ModuleGoVersion
   and Stale (R-FW-011 designed memoisation; Lock's own decode, which mutates, is not memoised).
5. **Jobs.Modulo memoised by drv path (A364)** pkg/engine/outputs.go: a drv path names its
   ATerm, so hashDerivationModulo of a path never changes; output generators hashed every input
   edge again (graphql TS job -> npm tool derivations). Mutex-guarded map.
