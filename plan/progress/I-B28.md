## DECISIONS
- A190 The UI is embedded from internal/ui/dist, not from web/build directly: go:embed cannot
  name files outside the package directory and R-ARCH-001 forbids a Go package in web/. dist/
  carries a committed .gitignore so `//go:embed all:dist` always matches (fresh checkouts compile,
  `go vet ./...` runs before the web stage); `all:` is needed for `_app/`. A binary built without
  the web build serves 503 with a hint on UI paths (never crash; API unaffected). Same pattern as
  pkg/engine/store/nixbin (gitignored payload written by a build step outside go build).
- A191 SPA routing: prerendered `<path>.html` before the fallback (adapter-static writes
  login.html for `/login`, SPEC: prerender only `/login`); missing `/_app/*` → 404 instead of
  200.html, so a stale chunk or asset request gets a plain 404 rather than HTML served as a
  script; other unknown paths → 200.html with status 200 (R-UI-001).
- A192 Security headers are not specified in SPEC; chosen: per-page CSP with sha256 hashes of the
  page's inline scripts (SvelteKit's start script, app.html's theme script) computed when the
  server loads the build, so no 'unsafe-inline' for scripts and no build-time coupling;
  'unsafe-inline' for styles (markup has `style="display: contents"`, components set style
  attributes for dynamic values, AGENTS.md §8); `img-src data:` for the inline favicon;
  form-action deliberately not set: the consent form's 302 goes to the CLI's loopback redirect_uri,
  which form-action would block. nosniff and Referrer-Policy same-origin on every UI response.
- A193 internal/http: a route pattern equal to a pending prefix replaces it (generic; used for
  "/"). "GET /" could not be used: it conflicts with the pending "/oauth/" etc. in ServeMux
  (neither is more specific), which panics at registration.
- A194 The web build mirrors web/build into internal/ui/dist from svelte.config.js (adapter
  wrapper) rather than a separate `go generate` step: tools/ci (protected) and the test harness
  run `vite build` and `go build` respectively and nothing else, so only a hook inside the vite
  build keeps the embed current for CI and tests without editing protected files. The mirror only
  runs when ../internal/ui/dist/.gitignore exists; web/build itself is unchanged by it.
- A195 `kit.version.name` is a content hash of the sources instead of a timestamp: reproducible
  output (§03 determinism; owner asked to keep the web build reproducible) while a source change
  still changes the version, so SvelteKit's version check still notices a new deploy.
