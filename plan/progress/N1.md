# N1 — install via Nix: flake, nixsystem build variant, GitHub Actions

Owner decision (chat, 2026-10-24, A439): flake + flake.lock at the root, NixOS usage, ci.yml and
release.yml, and a build variant that does not bundle Nix. ADR: docs/adr/0002a-flake-variant-system-nix.md.
Decisions: plan/decisions.md A440-A447. Caches/TMPDIR under /var/tmp/N1 (deleted at the end). No git
commands in the shared repo, no `bob lock` / `bob check --fix` at the root.

## NEEDS (for the coordinator / owner)

1. **`bob lock` at the root (coordinator).** Root bob.go now defines `AppImage` (label `//:bob`,
   `.github/workflows/release.yml` builds it). bob.lock has no entries for it yet. Lock result
   measured in a private copy: see "AppImage in a private copy" below. Until the root is re-locked,
   release.yml fails at `bob build //:bob`.
2. **Commit `flake.lock` and `.github/` with the rest** (the flake reads only tracked files when
   used as `github:megakuul/bob`; every file the build needs is tracked already).
3. **Owner item: a dedicated diag code** for "the Nix this bob was built with is unusable" (now
   BOB-E-1026 `nixpkgs mismatch: {what}` with the fix as hint, A442). Needs codes.lock,
   tests/golden codes.golden and SPEC §02.3 (protected).
4. **First real run of the workflows** happens on GitHub only (not testable here): x86_64 runner
   behaviour of `nix flake check`, the AppArmor sysctl on ubuntu-24.04 runners, and the x86_64
   build of bob-builder (the table check guards it). The release job needs `contents: write`,
   which is set on the publish job only.
5. **bob version in the flake build** prints `v0.0.0-dev` (BobVersion reads module build info;
   buildGoModule builds a `(devel)` main module). If the owner wants a real version there, eval
   needs an ldflags-settable version (pkg/engine/eval, not N1's).
6. Users must not override bob's flake inputs (`inputs.bob.inputs.nixpkgs.follows`): the Go must
   reproduce builders.go and the Nix must be a static 2.34. Documented on the install page.
7. `pkgs.system` in the owner's NixOS snippet evaluates with a deprecation warning on current
   nixpkgs (`'system' has been renamed to 'stdenv.hostPlatform.system'`); the docs show the
   owner's snippet and mention the newer spelling.
