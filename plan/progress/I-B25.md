## DECISIONS (coordinator: copy to plan/decisions.md)
- A152 `bob pipeline run <name>`: steps are build (Targets ∪ release labels of Releases) then test
  (Tests), each rendered like bob build / bob test under `== step <name>`; the first failing step's
  exit status ends the run. A pipeline with no Targets, Tests and Releases builds and tests `//...`
  (SPEC R-CLI-012 acceptance; the worker still runs nothing for such a pipeline: NEEDS 6). --json:
  one run.start, the steps' events, one run.finish with summed counts (no step event: schema v1 has
  none). Unknown pipeline: BOB-E-0001 kind=pipeline, exit 2. `--remote`: BOB-E-9008 (the framework's
  RemoteExecutor submits patterns, not pipelines; M16).
- A153 bob's `ci` pipeline: targets = the three binaries and //web:web; tests = the 49 Go packages
  whose tests pass inside the build sandbox (list `hermetic` in bob.go, measured: 39 of 56 pkg/,
  9 of 26 internal/, 1 of 2 cmd/) + //web:svelte-check. The other tools/ci stages (lint,
  layering, licences, buf, goldens, acceptance, budgets, protected report, the remaining unit
  tests) need the network, git, Nix, RustFS or files outside the test's package and stay in
  `go run ./tools/ci`, which is therefore still the done-criterion until they move.
- A154 Evaluator in bob's own repository: its main module is named `bobrepo` instead of
  github.com/megakuul/bob, so bob.go files compile against the running bob's framework
  (R-FW-043.4) and IR bobVersion matches (before: "the evaluator is bob (devel), this is bob
  v0.0.0-dev", BOB-E-9004).
- A155 bob-builder: Ctx.MkdirAll tolerates a directory another goroutine created between its
  Lstat and Mkdir (go-compile builds a module's packages in parallel). Before: random
  `mkdir …/pkg/github.com/…: file exists` failures of go-github.com-ulikunitz-xz, pierrec/lz4,
  aws-sdk-go-v2/service/{s3,sts} module derivations. BuilderVersion 13 → 14, builders.go regenerated
  (aarch64 frkhg2bg…-bob-builder-14, x86_64 192iq1qd…-bob-builder-14).
- A156 Sources: `.git/info/exclude` unreadable because `.git` is a file (linked worktree,
  submodule) counts as absent; a `.git` file is never a source (it names a host path). Needed for
  the bootstrap test's git worktree checkout.
- A157 Evaluator go directive: a root go.mod naming a patch release above the pinned Go (go.mod
  `go 1.26.9`, nixpkgs go 1.26.8) is clamped to the toolchain's version in .bob/eval/go.mod (before:
  BOB-E-9004 "requires go >= 1.26.9 (running go 1.26.8; GOTOOLCHAIN=local)"). Language-only
  versions were tried and rejected: dependency bob repos with `go 1.26.0` then need `go mod tidy`.
