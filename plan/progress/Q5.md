## DECISIONS (A540+)
- A540 Internal packages: per-internal-root registration stubs (`<root>/_bobeval`, chained) instead
  of evaluating main from inside the module tree (main must import every package; a single
  location cannot satisfy two disjoint internal roots).
- A541 codes.lock line of 1020 rewritten `hint=-` → `hint=hint` (the lock file says lines are never
  rewritten; the owner approved this hint template; message arguments, class and code unchanged,
  which is what R-NIX-028 protects).
- A542 Hints of ext.Errorf errors use a message convention (last line `hint: <text>`) instead of a
  new exported ext function: no new public API string parameter for TestRFW072 to classify, no
  API index change; ext's doc comment documents it. A code-less error naming a package gets
  DefinedAt (`package defined at <file>:<line>:<col>`) with the column of that package's
  constructor call; the `-->` location line stays.
- A543 cc: refused include/library path flags carry a hint (depend on the library through Deps;
  for libraries also the typed nixpkgs form).
- A544 The root go.mod requires the framework also when a Go module owns it (SPEC R-FW-043.4 "the
  generated root go.mod"), at bob's version including v0.0.0-dev, plus bob.Import modules, with
  go.sum lines; nested workspace modules do not (their `go list -m all` must equal bob's build
  list, R-GO-002b). bob's own repository (root module = framework) does not require itself.
- A545 bob's own repository imports its bob.go packages by the framework module path
  (`github.com/megakuul/bob` = the root bob.go package); R7 accepts such an import when the
  directory holds a bob.go (framework packages never do) and the evaluator rewrites it to the
  `bobrepo` self module (A154).
- A546 `bob version` human output: `nixpkgs nixos-26.05 (typed packages from <rev12>)` (one line, no
  new line keyword); JSON `nixpkgsSurface` = full revision. schema/events-v1.json (protected)
  does not list the field; it allows additional properties, so the stream validates (NEEDS).
- A547 bob's own build definitions follow ADR 0020: binaries in cmd/<x>/bob.go, the AppImage
  reaches //cmd/bob:bob through the slot `bobrepo.Bob`, tests as recursive sets per region
  (labels //<dir>:go_test unchanged, so the ci pipeline and flake.nix hermetic lists stay valid).
- A548 On-demand locking (bob build/test/dev/gen without a section, and --lock) evaluates the
  whole repository once more and resolves with its nodes of the ecosystems the request uses: a
  section always describes the whole repository, as after bob lock. Cost: one extra (cached)
  evaluation only when a section is missing; an unrelated broken bob.go then fails that first
  build like bob lock would.
- A549 cc dev share: realise the direct nixpkgs dependencies of the C/C++ packages (all outputs,
  GC-rooted under .bob/dev/gcroots) so compile_commands.json's include directories exist.
