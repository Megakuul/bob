- The claim works: the job was claimed 6 ms after "build planned" (ListJobs, claimedAt). The
  worker logs nothing at Info while a job runs. The job ran, but a fresh worker needed 1m43-2m05
  from the submission to the first output line, a warm one still 1m28 (job-run process tree
  sampled every second, private probe test in /var/tmp/I-B37/repo).
- Cause 1 (A290): the evaluator's trusted seed GOCACHE (os.UserCacheDir) lived below HOME=/root
  of the job container, deleted with every job: every job compiled the standard library (~40 s).
- Cause 2 (A292): a repository without a nixpkgs pin (every srvtest repo; any remote job of an
  unpinned repo) downloaded and unpacked the whole nixpkgs tarball in every job only to record its
  narHash (~30-40 s).
- With both: warm job first line 4.2 s after the submission (was 88 s); cold 83-95 s.
- Cause 3 (A293): the 2 MiB trigger counted 64 bytes of row overhead per line: 1,966 lines of
  1,000 bytes triggered, the test wants >= 2,000 (2 MiB of lines, SPEC "10,000 lines / 2 MiB").
- The windows (60 s / 90 s from the first submission on a fresh stack) still held the cold start:
  correction 72 (warm-up build first). Result: both tests PASS (shared tree; final run below).

### (2) TestRSRV102Membership: backoff alignment, plus dead-connection detection
- Added (A291): HTTP/2 health check on the Attach client (SendPingTimeout 10 s, PingTimeout 5 s),
  a 75 s silence watchdog on the stream (orchestrator pings every 30 s), cancel before
  CloseRequest/CloseResponse, the stream end logged at Info. Unit test
  TestAttachClientDetectsDeadConnection (frozen TCP relay; detected in 15 s; mutation: 60 s+ FAIL).
- The actual cause of the flaky redirect phase (debug run in a private copy, attach proxy and
  worker instrumented): phase 1 drove every worker's reconnect backoff to 30 s; the redirect
  reset the streams at T, the workers slept exactly 30 s and reconnected (to the redirected front,
  then refused) at T+30.0 s, the moment the test samples (it sleeps 30 s after the same reset):
  "3/4 streams". Fix (A291): a stream the server accepted (Welcome + valid pin proof) resets the
  backoff to 1 s, and every reconnect delay is jittered in [d/2, d]. Result: PASS 3/3, plus PASS
  in the triage run and the final run; the workers log the pin refusals.

## DECISIONS (coordinator: copy to plan/decisions.md)
- A290 internal/worker process.go jobEnv: job containers get XDG_CACHE_HOME=/bobhome/xdg/cache
  (the slot's state home, persistent like the store and drv cache), so os.UserCacheDir (the
  evaluator's trusted seed GOCACHE, npm caches) survives the job. Unit test
  TestJobEnvCachesInSlotHome.
- A291 internal/worker attach.go: HTTP/2 health check on the Attach client, 75 s silence
  watchdog, cancel before close, stream ends logged at Info; backoff reset after an accepted
  stream (Welcome + pin), reconnect delays jittered in [d/2, d]. Tests TestAttachClientDetects
  DeadConnection, TestAttachJitter.
- A292 pkg/engine/build gotool.go: the nixpkgs pin of an unpinned build is remembered per
  declaration below the store's state home (cache/nixpkgs/pin-<h>.json); the channel's current
  revision is still asked every time (PinNixpkgs update=true) and the memo only spares the
  narHash download when the revision did not move. Test TestPinMemo. (I-B39 owns the package and
  kept it when it added its go memo.)
- A293 internal/logstore writer.go: the 2 MiB commit trigger counts the buffered lines' text;
  the memory bound (MaxPending) keeps the row overhead. Test TestSizeTriggerCountsLineText
  (mutation-checked).
- A294 test correction 72 (warm-up build in the two R-LOG-001 tests).
- A295 pkg/cli server.go envTokenCache (+ cmd_info.go openStore, creds.go netrcHost): with
  BOB_TOKEN and a server (--server/BOB_SERVER/default) that has no stored login, WhoAmI with the
  token is its R-NIX-029 pre-check (same 4008/4010/4009 outcomes) and its announced cache becomes
  a substituter of the run, authenticated with the token in bob's netrc; nothing is written to the
  credentials file. Test TestEnvTokenCache.
- A296 internal/worker jobrun.go: no "<action> <label>" line of bob's own at package start in
  the package log (R-LOG-102 and the forged-chunk test compare the log with the build's lines).
- A297 internal/build builds.go: Create repeats a CAS that lost all its rounds (pctr/<project>,
  bidx/running, the build page, the branch counter) up to 8 times; internal/project ForUpload
  repeats the implicit project creation on ErrConflict (Create re-reads first, ends with
  ErrExists). Tests TestConcurrentCreate (30), TestForUploadConcurrent (40), both mutation-checked.
- A298 AnalyticsService/PackageDurations implemented: logstore.Reader.PackageRuns (run-<yyyymm>
  partitions of the range, fresh lake.Bucket each, filters project/label/start), aggregated per
  (label, UTC day) over runs that built (status ok/failed; cached and cancelled have no build
  duration); wired in cmd/bob-server parts_project.go. Tests TestPackageRuns (RustFS),
  TestDurationRows.
- A299 internal/worker jobrun.go: lines starting "bob-builder: " or "bob:: " (bob-builder's own
  diagnostics) and the worker's "✗ BOB-E-…" error line are not written into package logs; the
  errors stay in the job report / build record (R-LOG-003, R-CLI-008 "last 10 lines match the
  excerpt", which the engine computes without those lines).
- A300 test correction 73 (RFLEET008 store verify: binary path, store root, --no-trust).
- A301 classification: cold-worker timing, CPU and disk limits of this shared host are classed
  LOAD/ENV with the measurements above, not chased.
