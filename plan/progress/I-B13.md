## DECISIONS
- D-IB13-1 Project of a `--remote` build: the suites never create one (R-DEV-005 dir "remote" with a developer
  token holding only BuildService/* etc. on "*"; srvtest/chaos "repo" and R-CLI-008 "lines" as admin; srvtest
  stacks are not seeded). The first upload build (CreateBuild with source.upload_sha256 whose snapshot exists)
  of an unknown project id creates the project without a repository (display name = id). RBAC is unchanged:
  the caller already passed CreateBuild on that id (only principals with a "*" binding can name an unknown id),
  the record grants nothing (bindings are by id), and admins see it in ListProjects and can link or delete it.
  Rejected: (a) builds of non-existent projects (phantom data that ProjectService cannot list or delete, the
  printed /p/<project>/builds/<id> URL would 404); (b) requiring CreateProject as well (R-DEV-005's developer
  role lacks it; seeding a "remote" project to match a test directory would be tailoring). Owner may overturn.
- D-IB13-2 The upload body is spooled to a temporary file and hashed before anything is written, then
  written create-only: a wrong upload never exists in the bucket even briefly (SPEC: "object deleted"), and the
  write uses the existing signed-PutObject path (a streamed unsigned PUT over plain-http RustFS is unverified).
  Disk use is bounded by 4 parallel uploads × 512 MiB.
- D-IB13-3 Upload authentication: Bearer API credentials only (bob_at_, bob_sa_ api scope, bootstrap token);
  bob_dt_ / download-scope tokens → 401. Without CreateBuild on the project (NoAccess or Denied) → 404.
- D-IB13-4 WhoAmI.nix is nil when the server has no cache keys (no cache or key index unreadable); substituter
  "" without server.base_url (the CLI falls back to <server>/nix, I-C1 cleanNix).
- D-IB13-5 Build ids `b-` + upper-case ULID; job ids `<buildID>.j<nnnn>`; parsers accept legacy lower-case ids.

## NEEDS
1. pkg/engine/eval (rules.go R2, changed 19:59): the root bob.go must now be `package <root dir name>`
   (expectedPkg(root, ".")). On a worker the source is unpacked/checked out into `<job>/work/src`
   (internal/worker workSrc), so every remote or forge build whose root package is not `src` fails with
   BOB-E-1024 "./bob.go: package lines, but the Go code in this directory is package src" (seen with the
   tests/cli `lines` fixture; srvtest's `package srv` and devenv `package remote` are hit the same way). The
   root's expected package must not depend on where the tree lies: e.g. the last element of the go.mod module
   path (all suite fixtures match it), or skip R2 for "." without real Go code. Owner: eval rules (or worker
   unpacks into a dir named after it).
2. Worker speed: a one-package remote build takes 3–4 min in the job container (2 min 41 s with a warm slot home,
   output already cached). tests/cli R-CLI-008 runs two remote builds inside a devstack whose context ends after
   5 min (tests/devenv R-DEV-005: 8 min for three). Evaluation inside the job container is the cost (worker /
   engine owners); not addressable in the upload/API path.
3. S3 lifecycle `src/` → expire 7 days (§05.2.4) and `staging/`: no code or deploy doc applies bucket lifecycle
   rules yet (R-STORE-105 says "when the backend supports it"); deploy/setup owner.
4. tests/serverenv/stack/seed.go still PUTs the seed snapshot with the root key; it could use PUT /upload now
   (harness owner; not required).
5. Registry (M16.3): tests/ui expects an OCI tag `b-<build id>`; with ids now starting `b-`, the tag should be the
   build id itself (not `b-b-…`).
6. SPEC text: build ids `b-<ULID>` in §6.1 (example already in §02.6); `--remote` project = BOB_SERVER_PROJECT /
   dir slug + implicit creation (D-IC1-5, D-IB13-1); upload answers 201 on create (§6.9.7 names only 200/400).
