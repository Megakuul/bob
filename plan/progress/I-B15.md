# I-B15 — internal/store re-based on the dynamitedb library (A111; ADR 0011a rejected)

## Final design (internal/store)
- **Library calls only.** Every record read and write is a dynamitedb call: `store.Get` =
  `dynamitedb.Get` (key-only filter value), `store.Create` = `dynamitedb.Create`, `store.PutOwned`
  = `dynamitedb.Put` without ETag, `store.Delete` = `dynamitedb.Delete` with the ETag, `store.CAS`
  = `dynamitedb.Get` + decide + `dynamitedb.Put` with the read's `ETagField` (or `dynamitedb.Create`
  when absent). The hand-written request layer (old bucket.go get/put/del, record.go encode/decode,
  the plain-string model reflection) is gone. go.mod requires `github.com/megakuul/dynamitedb v0.6.1`.
- **One struct type per record kind** with `KeyField` `pk`/`sk` tags, `ETagField`, `DataField[T]`
  (all `omitempty`): store/records.go, store/identity.go, and the kinds owned by other packages
  (forge/integration, project, notify, overview, promote, orchestrator, build, rbac), which use the
  store aliases `store.KeyField/ETagField/DataField` because only internal/store may import
  dynamitedb (R-STORE-106, lint dbusage). New document kinds for the primitives: QueueTail (qt),
  QueueHead (qh), RegTail (wrt), PromoTail (promot), PromoEntry got keys (promo/<day>/s/<seq20>),
  BuildPage (bpage), BranchPage (bbr), UserIndexPage (uidx), project indexPageRecord (pidx),
  ActiveJobShard (jact), WorkerIndexShard (widx), notify outboxShard (nout), promote promoLock
  (plock, now with lease fields).
- **Fresh values vs fetched values.** Callers build update values with `store.Set` / `store.ID`
  (dynamitedb.Set / dynamitedb.Key re-exported for packages that may not import the library) and
  read fetched records with `.Value()`. Every record type has a `Draft() *T` (keys, ETag,
  `store.Carry` of every data field) = the fresh value that writes a fetched record again.
  internal/store/draft_test.go checks that every Draft names every field.
- **CAS write value.** A CAS func may return a fresh value, or the fetched record (or a copy, also
  of an earlier read) with some fields replaced by `store.Set`; `writeValue` keeps the operators and
  writes the fields that still hold read values through `Draft` (a field is a read value when its
  dynamic type is that of the freshly read record's field). After a write CAS returns the record as
  stored (one extra GET), because an update value cannot be read; `store.Change` is the same
  CAS without the read-back, used by every caller that discards the result (73 sites, incl. the
  worker claim, which takes epoch/attempt/spec from its CAS func): R-FLEET-009 budget.
- The store's S3 client: SDK standard retryer, 3 attempts, no client rate limit, backoff capped at
  100 ms (with the SDK default of 20 s the fleet suite ran 3× slower: budget test 162 s, 28.7
  requests/job, chaos lost 57–75 jobs; with the cap: 48 s, within 26, chaos as baseline).
- **Generic primitives over record types, record kind via builder functions**: `NewCounter[H]
  (build func(n) *H, n func(*H) uint64)`, `NewSeqLog[S](b, slot func(seq) *S, tail, head
  *Counter)`, `NewPagedIndex[P,E](b, p, build func(k, []E) *P, entries func(*P) []E)`,
  `NewShardSet[S,E](b, n, build func(sh, map) *S, entries)`, `NewLease[L](b, build func(LeaseState)
  *L, state func(*L) LeaseState, owner, ttl)`, `NewControllerLease(b, name, owner, ttl)`. The key
  value of a document is the builder's result with only its key fields kept (keyOnly).
- **What the store adds (docs/dynamitedb-lake-usage.md "bob wraps nothing except")**: recover around
  every call (`store.Call`, R-STORE-005), bucket split/credentials, the conformance probe (raw S3,
  probe.go), GET If-None-Match of GetCached (raw S3, then dynamitedb.Get on 200), bounded retries
  around ErrConcurrencyConflict, ctx first after a failed call (S9 B11), 404 of PUT If-Match →
  ErrNotFound (B13). Lost responses (R-STORE-103 rule 7): the store's S3 client (handed to
  `dynamitedb.NewFromClient`) has the SDK standard retryer (3 attempts, no client rate limit) and a
  context-scoped wire log middleware (attempts/status per operation, PutObject body); when a write
  attempt's answer was lost, dynamitedb reports the retry's 412 as ErrAlreadyExists /
  ErrConcurrencyConflict and the store re-reads the key raw: byte-identical to what it sent =
  success. The wire log also tells `dynamitedb.Delete`'s 404 (missing key → ErrNotFound) apart.
- fsck (`bob-server store fsck`, orchestrator.Fsck/CheckRecord) reads records through `store.Get`
  (dynamitedb decodes) instead of decoding raw bodies into record structs; objects of other kinds are
  checked raw with `store.ReadRaw` + `cbor.Wellformed`; `store.OpenUnprobed` for the operator
  command. internal/orchestrator no longer imports the S3 SDK for fsck.

## Deviation from the coordinator's guide (on purpose)
- The task text and docs/dynamitedb-lake-usage.md say "CAS = Get + Update with the ETag". The
  locked ADR 0011 (decision 2: "Get then Put with ETagField, one PUT If-Match"), SPEC R-STORE-103
  rules 4 and 5 ("dynamitedb.Update is not used") and the protected test
  tests/store/records_test.go TestRSTORE103SourceRules (fails on `dynamitedb.Update(` in
  internal/) all require Put. Precedence (AGENTS.md: SPEC > locked ADRs > plan) → CAS uses
  `dynamitedb.Put` with the read's ETag on a fresh value. Same library, 2 requests per uncontended
  CAS write instead of Update's 3 (+1 read-back GET in the exported CAS). The guide should say Put.

## Caller migration (mechanical, then by hand)
- An AST rewriter (go/types) turned field reads into `.Value()`, writes into `store.Set(...)`
  (typed `Set[T]` for constants, `nil` stays nil = absent field), key literals into `store.ID`,
  ETag reads into `store.ETagOf`, rewrote the record struct types and generated the Draft methods.
- A second checker found what the compiler cannot: a field read after it was set to an operator
  (sequential or in a loop), fields read on fresh values (literals, `*Key()` builders,
  "if cur == nil { cur = XKey() }"), fresh values returned or passed to readers. Fixed by editing
  plain locals and setting once (build controller closures, applyReport/withRow, setLast, index
  closures in auth/notify/forge, checkout shards, fleet cfg keys, settings), re-reading created
  records before answering (auth roles/SA/OIDC providers/users, forge, notify, project, build),
  plain-value refactors: forge `Config` (adapter settings), project `repoLink`, registrar `issue`
  parameters, `fleet.SignHeartbeat(key, wid, at, jobs)`, project `Linker.Health` instead of
  `Record`, settings `zero()` for the absent record, promote `SigningKeyIndex.Entries()`.
