## Analysis of the failures (traces with runtime/trace and pprof of a private build)
- **A300 (fixed)**: every no-op run rewrote .bob/gen/manifest.json with two fsyncs: readManifest
  turned a finished root's `"pending": null` into `{}`, so `before != after` always. SPEC §03.6.6
  says "final manifest (atomic; skipped if unchanged)". Go fixture no-op 1.8-2.6 s -> 0.95 s under
  load 17 (the fsync+chmod blocked 0.5-0.6 s on the loaded disk). Regression test
  TestNoopKeepsManifest (fails without the fix).
- No-op builds (B-007, B-016/021, B-045): time is in Nix subprocesses, ~20-50 ms each under load:
  ~25 `nix-store --check-validity` calls per Go-fixture no-op (srcs.Import per test/binary group,
  fetch.valid per fetched input), `nix build` of all installables even when every output is valid
  (0.2-0.85 s), tarball planning's closure query (0.79 s on polyglot). Not cheap fixes; options for
  the owners: (R1) check output validity first and skip `nix build` when all are valid; (R2) batch
  fetch validity (one call per ensureAll/moduleTree batch) and memoise valid paths per run;
  (R3) one srcs.Import validity batch across ecosystems.
- B-049 `bob gen` no-op 4-10 s: 191 fetch.valid subprocess calls (134 distinct; GeneratorModuleOf
  makes a new planner per generator and checks every gqlgen/graphql-codegen module again) ->
  R2 applies (biggest single win).
- B-001: a key hit still starts the cached evaluator in evalbox (~100 ms) plus a validity call for
  the Go toolchain (~35 ms); design, not a bug.
- B-087: 14.87 MB with DefaultPrune vs 12 MB; the protected TestROUT007Pruning asserts the same
  limit (NEEDS: pkg/output/appimage owner).
- B-080: 17.6 ms p95 on load 10, median 14 ms; likely within budget on a quiet host (re-measure).

## DECISIONS (coordinator: copy to plan/decisions.md)
- A300 materialise: a finished root's empty Pending reads back as nil, so a no-op apply does not
  rewrite the manifest (SPEC §03.6.6 "skipped if unchanged"); regression test added.
- A301 budget benchmarks live in tools/budgetbench (tools module, drives the bob binary like
  outbench/devbench; server rows use the dev-stack / RustFS packages of tests/serverenv and
  internal/{orchestrator,worker,store} in-process); persistent work dir `$BOB_BENCH_DIR`
  (default ~/.cache/bob-budgetbench), one untimed warm-up per measurement, results also in
  out/budgets/<group>.json with host and load; registering a row = benches.go entry + budgets.json
  regenerated with budgets.Write (bench field only; the file's note prescribes this).
- A302 correction 71 (TestBudgetStagesPass runs a stub, not the benchmarks).
- A303 B-058: the idle workers' starts are spread over one heartbeat period; with simultaneous
  starts the window edges coincide with every worker's timers (0 or 20 extra heartbeats: 0.1667
  and 0.1525 measured). The SPEC design rate (4 heartbeats + 2 polls + 2 config + 1 record per
  minute) is exactly 0.15 = the limit, with 0 count tolerance: the row passes only at the limit.
- A304 B-001 is measured on a generated repository (root bob.go + 999 directories with one
  trivial bob.Run step each, the R-FW-020 chain shape), bob.lock pinned by `bob lock` in the
  scratch copy (unpinned, each evaluation asked the channel over the network: +0.2 s), value = the
  `eval` event's durationMs with cached=true (`bob graph --json`), median of 5.
- A305 B-075 (evaluator defaults) is a configuration budget: the bench reads
  evalbox.Limits{}.WithDefaults() (what the local build uses: it passes zero limits) and checks
  all five clauses; the row value is the wall clock.
- A306 B-097: initial JS/CSS = the files web/build/200.html references plus their static imports
  (transitively), gzip -9; CSS ≤ 30 KiB checked in the bench; FCP not measured (no browser);
  the bench warns when web/src is newer than web/build.
- A307 B-038, B-083 not registered (above); B-019 ([2c/4G] hook p95) gets devbench's hook value.
- A308 B-068: one public path is published the way promotion leaves it (nix/vis/<hash>.json with a
  public release + nix/narinfo/<hash>.narinfo, written with the stack's root key) and fetched
  anonymously; 50 warm-up + 300 measured; p99 ≤ 20 ms checked in the bench.
- A309 B-057/B-088: the bench polls job states through a second, uncounted connection to RustFS,
  so the per-job count holds only protocol requests (workers, dispatcher, finalise); 300 jobs, 20
  workers with hour-long timers, wake-ups on, as TestRFLEET009RequestBudgetPerJob.
