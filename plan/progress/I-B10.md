## TEST PROBLEM
1. tests/forge/adapters_test.go githubCases / TestFixturesRefused: the GitHub fixtures are looked up as
   `file("push.branch.json", …)`, but forgefix.Load names body-only deliveries without ".json"
   (`stem = strings.TrimSuffix(n, ".json")` → "push.branch"), so every GitHub case and the whole
   TestFixturesRefused stop with `harness error: fixture github/webhooks/push.branch.json missing`.
   Evidence: a scratch copy with the names stripped of ".json" passes every case (GitHub, Forgejo,
   GitLab refusals included) except (2).
2. Same file, case "github push": fixture push.branch.json has `"created": true, "before": "000…0"`
   (a branch creation push), but the want leaves `created` false → `Push created/deleted = true/false,
   want false/false`. Fix: `created: true` in that row (the adapter reports the payload's flag).
3. tests/forge/forgejo_live_test.go "webhook": the seed (tests/serverenv/forgejo, collaborators map)
   makes bobbot a `write` collaborator on alice/demo; Forgejo serves repo hooks only to repo admins:
   `forge rejected bob's credentials (HTTP 403): user should be an owner or a collaborator with admin
   write of a repository`. Fix: seed bobbot as `admin` on alice/demo (the admin guide must say the
   bot needs admin on linked repositories, or bob cannot ensure hooks).
4. Same file, "statuses": (a) the read-back struct `struct{ Context, Status, Description, TargetURL string }`
   never decodes Forgejo's `target_url` (encoding/json matches names case-insensitively but not across
   the underscore), so every row reports `target_url ""`; fix: tag the field `json:"target_url"`.
   (b) the want maps cancelled → "error", SPEC §6.9.2 (and S16 §5.3, measured) map Forgejo cancelled →
   `warning`; the adapter follows SPEC. One of the two must change (owner).
5. Same file, "checkout": GET /api/v1/repos/alice/other with the repo-scoped job token answers 404 on
   the nixpkgs Forgejo of the harness (`{"message":"The target couldn't be found."}`), not 403 as
   ruling G3 assumes; the git half of the check (ls-remote refused) passes. The token is limited
   correctly; the expected code is wrong for this Forgejo version.
6. tests/forge/gitlab_live_test.go "webhook": the signing token is whsec_ + base64("gitlab-live-signing-key-0123456789")
   = a 34-byte key; GitLab 19 refuses it on hook creation: `POST /api/v4/projects/1/hooks: 422 {error: Signing token
   is invalid}`. The S16 spike (and the recorded fixture SIGNING_TOKEN.test) use a 32-byte key, which GitLab accepts.
   Fix: a 32-byte key in the test. All other GitLab live subtests pass.
