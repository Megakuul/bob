## DECISIONS
- A210 Job containers substitute from the orchestrator that answered the job's
  GetCheckoutCredential: substituter `<that endpoint>/nix` (reachable from the worker, unlike
  base_url maybe), its public keys from AuthService/GetServerInfo (KIND_PUBLIC, asked per job
  over the same client, so key rotation needs nothing on workers), the job's download token in a
  per-job netrc (jobs/<id>/netrc, 0600, root) bound read-only at /etc/nix/netrc. The worker
  nix.conf written at start stays for jobs without such a cache; with one, a per-job nix.conf in
  the job dir lists it before cache.nixos.org (SPEC §05.8). All nix.confs now say
  `netrc-file = /etc/nix/netrc`. Workers cannot read the control bucket and keys rotate, so
  cmd/bob-server/parts_fleet.go cannot wire static Substituters/TrustedKeys: they remain as
  optional extra caches (documented on ProcessConfig); parts_fleet.go now wires the identity as
  the download-token issuer instead (`f.Checkouts.Downloads = id`). A cache whose keys are
  unknown is not used; any failure to learn the cache only logs a warning (the job builds what
  it misses). The netrc copy the engine reads in the slot home is removed at job end. The
  token is readable by root in the container only (evaluator: unprivileged uid + Landlock;
  builds: Nix sandbox).
- A211 Job download tokens: GetCheckoutCredential fills download_token for every job of a
  project (also uploaded sources: sealed_checkout stays empty there, as the SPEC says), via the
  new Checkouts.Lease (lease check first, nothing minted for a non-holder). Token = bob_dt_,
  TokenRecord {owner "job:<project>/<jobID>", kind dt, scope download, expires +24 h backstop}
  (auth.IssueJobDownload). It authenticates as a principal without bindings with
  api.Principal.CacheProject = project; the /nix/ handler lets such a principal see exactly the
  private paths of that project (internal/cache handler.visible); OCI, releases and the API give
  it nothing (no bindings; download scope refused on the API except WhoAmI). Only its handle
  (the SHA-256 record key) is recorded in ftok/<sh2(job)> as a CheckoutRecord with
  Download=true, so JobEnded and the forge-sweeper revoke it like forge tokens; the sweeper also
  revokes it when the lease moved on (epoch changed or job queued again), a repeated call
  revokes the earlier token. RevokeJobDownload deletes only records whose owner is a job.
  ExpiresUnix = the forge token's expiry for git jobs, else the download token's.
- A212 "Revoked at job end" = the forge-sweeper pass (≤ 60 s after the job is terminal, plus
  ≤ 10 s token cache), the same path forge tokens use today: nothing calls Checkouts.JobEnded
  (workers send no JobEvent FINISHED; see NEEDS 1).
- A213 Worker jobs pass bob's caches to the engine (EngineRunner: build.Options.Caches parsed
  from the container's nix.conf + netrc, every substituter but cache.nixos.org): bob derivations
  are never substituted by Nix itself (A71), so the engine's batch narinfo check + realise is
  the only way a job gets them. The engine now substitutes before it decides which test results
  are cached, and includes the selected test units' result paths in that substitution: a test
  result fetched from bob's cache counts as cached like a local one (also for CLI `bob test`
  with a logged-in server). Without this a retry on another worker re-ran B's test.
- A214 Root-mode nix.conf sets `narinfo-cache-negative-ttl = 0`: Nix's lookup cache lives in
  the slot home across jobs, and a path promoted a moment ago must substitute in the next job
  (retries). Cost: misses are asked again in every job.
