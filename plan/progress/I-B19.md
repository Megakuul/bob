### (2) Fleet reliability (R-FLEET-003, -001, -012)
Found with debug logging (removed again) in the chaos test, the reconciler and the registrar:
- **R-FLEET-003 "never run by another worker" = late requeue, not a lost job.** In every failing
  run the job was not lost: either the reconciler requeued the paused worker's job only after
  the pause (2 × TTL + 1 s = 7 s) ended, so the paused worker's late completion was legitimately
  accepted (its lease was still valid), or (once) the paused worker itself claimed the requeued
  job again after its lease-lost. No double acceptance, every job terminal, in all runs.
- Root cause of the late requeues (real latency, made worse by load): a reconciler pass took 4-17 s
  for 100-300 active jobs and checked the held jobs only at its start and end.
  (a) leaseExpired read the heartbeat and the worker record of every owner one at a time
  (up to 40 sequential GETs per pass);
  (b) every queued job of the chaos lab was re-slotted once, sequentially, inside the same loop
  (test bug below: the queue stamped `qa` with the injected 12:00 clock), each 100 ms-2 s.
  Fixes in internal/orchestrator/reconcile.go: `prefetch` reads the heartbeats and due worker
  records of all owners in parallel (16) and only advances the cached heartbeat on a verified
  signature (a requeue still confirms with its own fresh read); held jobs are handled before
  re-slots/finalising (`urgency` order); `sweepDue` re-checks the known held jobs every 100 ms
  between the steps of a pass (active set read, chunks of 32 job reads, each job) with the
  heartbeat reads of the due ones in parallel; the active-set ShardSet is kept across passes
  (its GetCached cache answers 304). Measured lateness after the deadline: was 1.5-4 s, now
  0.06-0.8 s.
- Worker (internal/worker/loop.go): a worker that lost a job's lease leaves the job's next open
  slot to the other workers (`skipLost`/`noteLost`): wake-ups and the spread pick skip it, the poll
  walk skips it once and keeps the head hint below it; a fleet without another worker runs it from
  the reconciler's re-slot (fleet.reslot_after). Memory bounded (10 min).
- Result: TestRFLEET003* (LeaseAndRequeue, ClaimGrace, Cancel, Reslot, Chaos both modes) green 4
  runs in a row at load 13-27 (previously the chaos test failed in nearly every run on this host).
- **R-FLEET-001: test artefact.** The 7.9-17 s outlier is always the first sample: workerProc calls
  harness.Bin, whose first call builds bob, bob-server and bob-builder inside the timed region
  (debug log: workers 2-20 approved 0.75-3.4 s after process start, first sample = build time +
  3.3 s). Registration itself: registrar pass every 2.0-4.2 s under load, approval ≤ 3.4 s. With the
  correction below: PASS (65 s run, load 13-17).
- **R-FLEET-012 wake p99: load artefact.** Same binary: FAIL p99 2.58 s / 1.49 s at load 24-30,
  PASS at load 21 (74 s run), PASS under `nice -n -15` at load 17-25 (117 s and 70 s runs). The
  critical path is ~10 sequential S3 requests (jact CAS 2, job create 1, slot append 3-4 incl. the
  tail-hint raise, claim CAS 2, start CAS 2); at 100 ms per request on the loaded RustFS the 1 s
  budget is gone. SDK retry/backoff (I-B15, ≤ 100 ms), lease TTL and reconcile interval are not on
  this path. Possible store-side savings in NEEDS.

### (3) Retention: cache GC
- internal/orchestrator/controllers_cachegc.go `CacheGC` (new): walks promo/<day> logs (no LIST;
  empty days probed in parallel, tail hint + slot; deleted slots below the tail are holes) from the
  persisted position (ctl/retention.cu, `retentionState.Cache`: first open day, per-day slot) to
  today. Rule per entry older than the retention and older than a 10 min grace (promotion appends
  the entry before it writes the narinfo): keep when the path is in the narinfo closure of a
  non-deleted release (`release.Releases.Retained`) or of a path promoted within the retention, or
  its visibility document lists a public release → the entry moves to today's log (judged again a
  retention later / next run with 0 days); narinfo newer than entry + grace → only the entry goes
  (collected and promoted again); else delete narinfo, listing, NAR, visibility document, then the
  entry. Releases' rel/ assets are never touched. Runs daily when the retention > 0 (each run reads
  the whole window), every hourly pass when it is 0. Narinfo references memoised (immutable).
- controllers_retention.go: `Retention.CacheGC *CacheGC`, `CacheSetting` hook; the state lives in
  retentionState.
- cmd/bob-server/parts_controllers.go: CacheGC over the artifacts bucket with its own VisStore and a
  release.Releases (Retained only); `cacheSetting`: retention.cache_unreferenced_days from the
  settings record when an admin set it (CacheNow = explicit 0 → collect now; value via
  overview.Settings.CacheDays), else BOB_RETENTION_CACHE, else 90 d.
- internal/orchestrator/controllers_cachegc_test.go TestCacheGC (RustFS): explicit 0 → only the
  unreferenced path goes (all four objects); released path, its reference, public-visibility path,
  recent path and its reference stay; re-promoted path's old entry dropped without deleting; days
  before yesterday closed; immediate re-run removes nothing; after the release is deleted (and the
  public release removed from the document) the next run collects the 5 paths; 90 d keeps a young
  path. Green.
- controllers.go: a Persist controller records a completed pass even when the orchestrator stops
  right after it (detached 10 s context); an interrupted pass is not recorded. Fixed the flaky
  TestControllers/persist (the successor repeated the hourly pass under load).

## DECISIONS
- D-IB19-1 The server's ecosystem list stays a second list (cmd/bob-server/link.go) checked equal to
  pkg/cli/link.go by a test (no shared package possible across the pkg/internal boundary).
- D-IB19-2 A worker that lost a job's lease skips the job's next open slot once (other workers take
  the retry; single-worker fleets get it from the re-slot after fleet.reslot_after).
- D-IB19-3 Cache GC reference rule: closure (narinfo references) of non-deleted releases and of
  paths promoted within the retention, plus a public release in the visibility document; kept
  entries move to today's log; 10 min grace; daily runs unless the retention is 0.
- D-IB19-4 Cache retention precedence: settings value when set (explicit 0 included) > env
  BOB_RETENTION_CACHE > 90 d.
