## DECISIONS
- A151 Registry tag visibility: a tag of `<project>/<image>` is visible iff the object's vis doc
  exists and the caller has GetRepository on `<project>`, or it is a release tag whose release id
  is in the doc's `public`; build tags are project-only. Same rule for manifest-by-tag,
  tags/list, RegistryService (ListTags/GetRepository) and the token grant. Digest references stay
  object-based (content-addressed, already visible through the public release; refusing them
  would not hide anything and would break pulls through a public tag of another repo). Reason:
  principle 5 (security boundaries structural) — the vis doc is shared by every project that
  builds the same bytes, so it cannot alone decide a per-project name. Consequence: a build tag
  of a project is no longer anonymously listable even when its digest is public (internal test
  updated). Also added to SPEC §6.7.
- A180 SPEC text for the job row error `e` (§05.4.4) and Job.error kept after the job ends
  (§6.5.7), describing what I-B23 implemented (first line, URL credentials redacted, ≤ 300 B).
  Observation: the §05.4.4 row list also omits `pm` (promotion) that the code has; not changed.
