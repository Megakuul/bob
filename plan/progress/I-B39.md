## What changed (all in pkg/engine, no SPEC signature changed)
1. **Validity memo per run (A310)** `store.(*Store).WithValidityMemo()`; `build.openStore` gives
   every entry point (Run, Gen, Dev, lock, status, native, sources) its own memo store. `Invalid`
   dedupes, answers known paths from the memo, asks Nix only for the rest (still one batched
   `nix-store --check-validity --print-invalid` per 2000 paths). Positive answers live for the run
   (bob never deletes store paths; a concurrent GC can remove an unrooted path after any check,
   with or without memo, exactly as after `nix build --no-link` exits). Negative answers live only
   until the store starts any command that may change it (everything but `--check-validity` and
   `nix path-info`: generation counter). `Import` success records its items valid. Unit test
   TestValidityMemo / TestReadOnlyCommands.
2. **Skip `nix build` when every requested output is valid (A311, R1)**: realise asks about the
   installables' outputs and all planned outputs in one batch; if all installable outputs are
   valid, the nix stage runs nothing (stage event still emitted), and the validity stage
   (R-NIX-018, success still decided structurally) is answered from the same batch. Event
   streams of no-op `bob build --json`, `--print-paths`, `bob test --json` on fixtures go and
   polyglot are byte-identical (minus time/duration) to the pre-change bob. A real edit
   (lib/strutil) still builds 6 derivations, the following run is a no-op with 1 Nix call.
3. **Batched fetch validity (A312, R2)** `fetch.StorePath`, `fetch.CheckValid` (one batch for all
   pinned requests); `ensureAll` calls it before the parallel Ensures.
4. **Evaluator's Go (A313)** go memo `<home>/cache/nixpkgs/go-<h>` (output path of nixpkgs go per
   revision+system, written from the index like the pin memo A292): used only when Nix reports it
   valid (checked in one batch with the nixpkgs source); otherwise the old path (Ensure source,
   index lookup, realise). Saves the 700 KB index parse and one Nix call on every evaluation.
5. **Validity hint + prefetch (A314, R2/R3 generalised)** `<home>/cache/drv/validity/<sha(cmd,
   root)[:12]>`: the paths a run of this command in this repository asked about; the next run asks
   Nix about all of them in one background batch while the evaluator runs (`store.Prefetch`;
   `Invalid` waits for it). Only Nix's answers of the current run enter the memo, so a stale or
   damaged hint costs only batch size. Written at the end only when the set changed, no fsync
   (best effort). Not used for Untrusted (worker) runs. Bounded: 100,000 paths / 16 MiB.
6. **CPU on no-op (A315)** `drv.normalise` converts generic value trees directly (JSON round trip
   only for other types; equivalence test vs the round trip incl. invalid UTF-8, floats, nil
   slices, structs, RawMessage); `store.ImportDrvsAt` checks validity by the known drv paths and
   serialises only missing drvs; `store.Builder` checks validity before gunzipping the embedded
   builder (a valid path holds what its name says; BOB-E-9007 still checked on every import, i.e.
   "at first use" per R-NIX-015); host nixpkgs index opened once per run; closures memoised per
   run (closure of a valid path is immutable; polyglot asked 3x the same `nix path-info`);
   cachedDeps one batch instead of one call per label.
7. **graph eval event (A316)** `build.Evaluate` reports the eval stage up to the end of the
   evaluator, without IR parsing, as `Run` does (R-FW-049 lists ir as its own stage); the IR
   parse of 1,000 nodes was ~30 ms of the old B-001 value.
8. **bob gen (A317)** the native-files phase and the working-tree phase share one evaluation,
   index, validity memo and hint (`runAfter`): before, bob gen evaluated twice and opened the
   index twice.

## DECISIONS (coordinator: copy to plan/decisions.md)
- A310 per-run validity memo in pkg/engine/store (positive answers for the run; negative until the
  next store-changing command); see item 1 for the GC argument.
- A311 skip `nix build` when all installable outputs are valid; validity stage still runs.
- A312 fetch.CheckValid batch before ensureAll.
- A313 go memo for the evaluator's Go (cache/nixpkgs/go-<h>), validated by Nix every run.
- A314 validity hint per (command, repository) in cache/drv/validity/, prefetched in background;
  hint chooses what to ask, never the answer; no hint for Untrusted runs.
- A315 CPU: normalise fast path, ImportDrvsAt, Builder validity-first, shared index, closure memo.
- A316 `bob graph` eval event excludes IR parsing (consistent with Run).
- A317 bob gen phases share evaluation/index/memo.
- A318 the evaluator's canonicalJSON (pkg/bob/irout.go) re-encodes the marshalled bytes directly
  (members sorted by decoded key, last duplicate wins, plain ASCII strings copied, every other
  string decoded and encoded by encoding/json) instead of decode-to-interface + encode. Proven
  equal to the old definition (kept as decodeEncode, used for invalid input): hand-written
  documents (whitespace, duplicates, \u escapes, lone surrogates, HTML chars, U+2028) and 20,000
  random values incl. invalid UTF-8 and structs (TestCanonicalJSONMatchesDecodeEncode); 20 IR
  documents of the 1,000-node repository byte-identical; `bob graph --json` of polyglot, codegen,
  eval1000 identical to the pre-change bob; tests/core TestRFW047FixtureIRIsCanonicalAndValid
  passes. Saves ~13 % of the evaluator's CPU. framework.zip regenerated (every eval key changes
  once).
