## DECISIONS (coordinator: copy to plan/decisions.md)
- A240 Go link (R-NIX-019 prevent/strip/reference check): binary links (not test links) run the
  linker with GOROOT cleared, as cmd/go -trimpath does (cmd/go/internal/work/gc.go; cmd/link
  then omits runtime.defaultGOROOT, the toolchain reference), and release links add `-s -w`
  (profile debug keeps DWARF). New bop Link fields `trim`, `strip`. The go-link job's fixup
  names the Go toolchain and bob-builder as forbidden references (builder reference check +
  outputChecks disallowedReferences, so Nix enforces it too); other Go jobs keep the empty fixup.
  The Go kinds still do not use the binutils strip step: `-s -w` is the linker's equivalent and
  needs no extra input. BuilderVersion 14 -> 15, builders.go regenerated.
- A241 Orchestrator key pinning (R-SRV-102, §05.9.1, S17 "cert pin"): each orchestrator process
  creates an Ed25519 key; fleet/cfg.m `fp` = hex SHA-256 of its SPKI. The worker sends a fresh
  32-byte nonce (header Bob-Attach-Nonce) on Attach; the orchestrator answers with header
  Bob-Attach-Proof = base64(SPKI).base64(sig over "bob-attach-v1\0"||nonce), sent with Welcome.
  The worker accepts the stream only if the proof verifies against the pin of the expected
  member: for fleet/cfg endpoints the member with that endpoint; for BOB_ORCHESTRATOR_ADDRS the
  member named in Welcome, and the address stays bound to the first member it proved (a
  redirected address is refused). After every stream end the worker closes idle connections, so
  a refused server keeps no connection. Why not TLS on the listener: bob-server serves plain
  HTTP today (no TLS config key exists in §05.11.1; §6.2 allows a TLS proxy in front), the
  devstack uses http:// everywhere; an end-to-end proof of the same SPKI-pinned key holds
  through a TLS-terminating proxy as well. Serving TLS itself is left to the listener owner.
- A242 CA certificates on hosts without a bundle (R-NIX-020 "zero setup", HARNESS §7.1: Ubuntu
  and Debian base images ship none, S8 §3.5): bob embeds the Mozilla bundle of nixpkgs
  nss-cacert 3.126 (pkg/engine/store/cacert/ca-bundle.crt, MPL-2.0, ATTRIBUTION row). (1) cmd/bob
  installs it with crypto/x509.SetFallbackRoots, which Go uses only when the system has no roots
  (bob's own HTTPS: channels.nixos.org, caches). (2) Nix gets no new env or nix.conf line (both are
  exact per R-NIX-024); instead, when /etc/ssl/certs/ca-certificates.crt (Nix's first default) is
  missing, store.Open writes Nix's second default, <home>/nix/var/nix/profiles/default/etc/ssl/
  certs/ca-bundle.crt (= /nix/var/... inside the namespace; checked in the embedded Nix binary's
  strings), with $SSL_CERT_FILE, else the host bundle at Go's known Linux paths, else the embedded
  bundle; written after the namespace probe succeeded (nothing below <home>/nix before, R-NIX-022),
  atomically, only when the content changes.
- A243 Prune check attribution (R-OUT-007 acceptance text "removes libssl.so.3, which api needs"):
  api loads libssl only through libfoo.so, so the per-file check named libfoo.so. The AppImage
  builder (entries) and engine.CheckPruned (OCI, new variadic `programs`) now follow the program's
  kept libraries (each resolved in its own RUNPATH) and name the program; files that are not a
  program keep naming themselves.
- A244 pkg/engine/eval/evalbox/watch.go (owner: evalbox; small named fix): the no-cgroup memory
  watchdog counts the sandbox's /work only when it is a tmpfs and not the caller's own /work. Before
  stage1 pivots, /proc/<pid>/root/work is the caller's /work (the rootless harness binds the repo
  there), and its used disk blocks were charged as memory -> false 2 GiB kill, rendered as 9005.
- A245 internal/worker/attach.go: Attach PoP path = "/api" + procedure (was "/api/" + procedure,
  a double slash the orchestrator never accepted); regression test TestAttachPoPPath. Each Attach
  stream gets its own client whose dialed connections are closed when the stream ends.
