# Gate H review, unit GH-C (ecosystems: R-GO, R-CC, R-RS, R-NPM, R-ML, R-GEN)

Reviewer did not write the tests. Scope: tests/eco/*, tools/regmirror. `go vet ./tests/eco/... ./tools/regmirror/...` and gofmt are clean after the edits below.
"Wrong impl" = an implementation that would still pass. NOT EDITED items are semantic or SPEC-ambiguous and need an owner decision before Gate H.

## Edits made (test-side bugs, minimal)
1. tests/eco/cc/clangd_test.go (R-CC-003a): the golden compare of compile_commands.json could never match. The fixture lives in a temp dir, but golden.Assert only replaces the repo root with $REPO, so `directory` stayed a random path. Added a golden.Normalize that replaces the fixture dir with $REPO (SPEC: "equals the golden after replacing directory").
2. tests/eco/golang/toolchain_test.go:~97 (R-GO-004a): "std built once per toolchain variant" was vacuous. The map was keyed by the unique .drv file name, so the count was always 1. It now keys by the name without the hash prefix, so a std derivation built twice with the same name fails. Caveat: if std legitimately differs by tags/flags without a name suffix, this could false-fail; the SPEC name pattern has no such suffix.
3. tests/eco/rust/tooling_test.go (R-RS-003a): the test accepted any one "unresolved ..." counter. It now requires counters for both unresolved imports and unresolved macro calls (SPEC: 0 and 0).
4. tests/eco/ocaml/build_test.go (R-ML-001a): the closure scrub check now also rejects glibc-*-dev (SPEC §03.5.3 lists glibc-dev among the scrubbed refs).

## Findings, ranked (NOT EDITED)

### High
- R-GO-004a, tests/eco/golang/toolchain_test.go:~118 (TestRGO004aRequirementNeedsNewerGo): BOB_GOPROXY points only at a dir containing github.com/foo/bar. The fixture's api module also requires uuid and the other modules, so a correct `bob lock` can fail first with E-RESOLVE (BOB-E-1015) instead of BOB-E-1008. This may keep the test red for a correct implementation (it passes only if bob checks the go directive before fetching the other modules). Fix idea: serve the registry mirror plus bar (e.g. copy bar into a chained proxy) or add a replace-free fixture that needs only bar.
- R-NPM-005a, tests/eco/npm/quirks_test.go:~96 (TestRNPM005aQuirkTestsPassInFixture): "Test passes in a fixture" is only checked as: build succeeded and the verbose output contains the substring "esbuild"/"better-sqlite3". Those names appear in any build log of //native:native, so an implementation that never runs the quirk Test passes. It also covers only those two names, not "each entry" of the table. Needs an observable (e.g. a Test with a marker/exit code, or a deliberately failing Test entry that must fail the build).
- R-NPM-010a, tests/eco/npm/dev_test.go:~100 (dependency restart): the loop succeeds when node_modules/left-pad/package.json exists and `GET /` answers. The old Vite process answers too, so an implementation that swaps node_modules but never restarts Vite passes. Nothing checks that the new package is importable through Vite (no module importing left-pad is requested). Needs a PID/start-time change or a served module that imports left-pad.

### Medium
- R-NPM-004a, tests/eco/npm/scripts_test.go:~100: SPEC "runtime closure contains only the .node file, glibc and libgcc beyond node". The test is a deny-list (gcc-wrapper, binutils, python, make, node-gyp, full nodejs, bob-builder). A closure that also holds e.g. bash, coreutils or openssl passes, and libgcc is never required. Should be an allow-list (node-slim, glibc, libgcc, the app's own npm derivations). Also "builds offline" is not asserted (the comment says the log must not show a download, but no assertion). Both denied and allowed paths use `bob run`, while SPEC says "the test fails" / "the test opens :memory:" (the native fixture has no test target).
- R-NPM-007a, tests/eco/npm/build_test.go: the ESLint (type-checked) test from the acceptance text is not asserted anywhere (only vitest is). Missed bullet. The fixtures also lack a Vite+React site in tests/fixtures/repos/npm (React is built from a generated repo, not the fixture).
- R-NPM-003a, tests/eco/npm/layout_test.go:~85 (Hoisted): only checks one hoisted drv and that index.html exists. SPEC: "the same app output runs"; the output is not compared with the isolated build and nothing runs. SPEC names the Vite+React fixture and `node_modules/react`; the test uses the Svelte site (svelte/acorn). Deviation is logged in the test comment, so it needs a SPEC/fixture decision.
- R-GO-003a, tests/eco/golang/tooling_test.go:~85 (`go mod tidy` drift): conditional. If tidy leaves go.mod/go.sum byte-identical, the test passes without any drift detection, so an implementation that never detects drift passes whenever tidy is a no-op. The test cannot tell which case happens; a forced change is needed (e.g. an extra unused requirement in the fixture bob.go-generated go.mod before tidy).
- R-RS-005, tests/eco/rust/build_test.go:~114: the cold dry-run uses a fresh BOB_HOME and no network. SPEC asks for network disabled and an empty crate cache. A fresh home also drops every other cache (nixpkgs index etc.), so this may be stricter than SPEC and red for a correct implementation. It also needs unshare(CLONE_NEWUSER|NEWNET) to work on the CI host. The graph-facts check (`withDeps == 0`) passes if a single crate has deps/features; SPEC says each crate entry stores them. `bob build --dry-run` is not in the CLI table (SPEC §02 `build` row): SPEC problem.
- R-RS-002a, tests/eco/rust/resolve_test.go:~30 and R-GO-002b, tests/eco/golang/resolve_test.go:~25, R-ML-002 corpus: corpora are author-chosen sets. SPEC wants the 4 S3 graphs (12/25/173/393 packages) for Rust, kubernetes/client-go + grpc-go + bob itself for Go, and "incl. the 8 S5 graphs" for OCaml. The Rust set has no size check and likely lacks the 173/393 graphs. The Go "bob" entry only requires bob's direct requirements from a scratch module, not bob itself as a workspace. Not weaker in count, but not the SPEC sets.
- R-GO-001a, R-CC-001a, R-RS-001a: SPEC says `bob build //... && bob test //...` natively AND cross. All three run `bob test` only on the host platform. "Every Go derivation rebuilds bit-identically" is compared only for the labelled top-level outputs, not each derivation (std, packages). R-RS-001a runs demo/usec/cmain checking only the exit code (output content never asserted); the "cgo binary calls the StaticLib" bullet is delegated to R-GO-001a (acceptable, noted in the test).
- R-GO-002b, tests/eco/golang/resolve_test.go:~52 (goIn): sets CGO_ENABLED=0, so `go build ./... && go vet ./...` skips the cgo package of the fixture (the pattern silently drops it). SPEC does not say cgo off. Network isolation is not enforced either (relies on GOPROXY being file/mirror).
- R-GEN-005, tests/eco/gen/generate_test.go:~265 (cost): SPEC is "added two-phase cost <= 0.5 s [8c/15G]". The test uses an absolute median of 5 builds <= 1.5 s (0.93 s baseline + 0.5 = 1.43 s). Slightly looser than SPEC and hardware-dependent (can be flaky on a smaller host); cannot measure the without-cutoff baseline. Needs owner decision (B-id in budgets.json?).
