# ADR 0006 — npm: bob's own resolver, one derivation per package instance, scripts denied by default

- **Status:** Accepted (locked) — owner at Gate S, 2026-10-21
- **Requirements:** R-NPM-001…010, R-DEV-001/002/006, R-NIX-001 (B), D15, D30–D34, D47, D51
- **Evidence:** `docs/spikes/s04-npm.md`, code in `spikes/s04-npm/`, numbers in
  `spikes/s04-npm/tmp/measure-8c.txt` and `measure-2c.txt` (rerun with `measure.sh`).

## Context

bob must install npm packages without the npm/pnpm/yarn CLIs (D15), with an isolated layout by
default (D30), lifecycle scripts denied unless allowed (D31), a small quirks table (D32), and
Vite live reload in `bob dev` (D34). Backend B (ADR 0001) computes derivations in Go. The spike
resolved six real graphs (69–411 packages), built them with B, ran tsc, Vite (React and
Svelte + workspace library), esbuild, vitest, ESLint (type-checked), a node-gyp addon
(better-sqlite3) and Bun, and ran the Vite dev server with HMR inside bob's namespace as a
non-root user.

## Decision (proposed)

1. **Resolution is bob's, in Go, at `bob lock` time,** against the npm registry's abbreviated
   metadata (`application/vnd.npm.install-v1+json`, ETag cache). Rules: node-semver ranges with
   the prerelease rule; `latest` dist-tag wins when it satisfies, else the highest satisfying
   non-deprecated version; an already chosen version is reused when it satisfies (npm's dedupe);
   breadth-first, alphabetical per level; optional dependencies are kept for all platforms
   (os/cpu/libc are recorded; libc comes from the per-version document because the abbreviated
   form lacks it); `npm:` aliases; bundled dependencies are not resolved (they come in the
   tarball); required peers are auto-installed (npm 7+), optional peers only link when present;
   workspace packages link by name. On six real graphs the result had **the same name@version
   set and 0 edge differences** compared with `npm install --package-lock-only` (npm 11.19.0).
2. **Package instances carry their peers in the key** (`name@version(peer@v,…)`, pnpm-style).
   Two importers with different peer versions get two instances. npm's hoisted tree gets this
   wrong (one shared copy resolves the wrong peer); bob's lock does not.
3. **Derivations:** one fixed-output `builtin:fetchurl` per tarball (sha512 from bob.lock);
   one derivation per package instance that unpacks the tarball to `$out/node_modules/<name>`
   and symlinks its dependencies (and peers) next to it; cycles are collapsed into one
   derivation (Tarjan SCC); one `node_modules` derivation per importer with direct-dependency
   symlinks and `.bin` wrappers that call node/bash by absolute store path. Node, TypeScript,
   Vite, Rollup, esbuild, vitest, ESLint and Bun resolved everything through this layout.
   **Hoisted copy is the per-importer fallback** (`npm.Hoisted()`), not the default: same disk
   use, but every dependency change rebuilds the whole tree (7.4 s vs 1.0 s measured) and no
   sharing between projects.
4. **Builders see `node_modules` as a writable directory of symlinks** (`cp -a` of the importer
   derivation), because Vite and others write caches under `node_modules/`. The working tree gets
   the same in `bob dev` / `bob build`, swapped in atomically, keeping `.vite`.
5. **Lifecycle scripts are denied by default.** A per-package allowlist in bob.go
   (`npm.AllowScripts("better-sqlite3")`) runs `preinstall`/`install`/`postinstall` (and the
   implicit `node-gyp rebuild`) inside the package derivation, offline, with bob's native
   toolchain (nixpkgs node, python3, make, cc, sed, grep; node-gyp from the npm bundled in
   nixpkgs node; `npm_config_nodedir` = node headers). Build intermediates are deleted so the
   runtime closure holds only `*.node` plus glibc/libgcc.
6. **Quirks table:** Go data shipped with bob, each entry with package, version range,
   justification, the action (skip the script / extra env / extra nixpkgs tools) and a test run
   in the package directory after the build. Two entries in the spike (esbuild: skip,
   better-sqlite3: build from source). Phantom dependencies are **not** quirks: users declare
   them with `npm.Extend(pkg, npm.Peer(dep))`, and bob's error translation suggests it.
7. **`bob dev` for Vite:** run the user's Vite inside the namespace through a bob-generated
   wrapper config that imports the user's `vite.config.*` and adds `/nix/store` to
   `server.fs.allow` (otherwise non-prebundled store files get 403). inotify works across the
   namespace: save → HMR update median 2.4–3.3 ms.
8. **Runtimes:** Node (nixpkgs `nodejs-slim` for outputs) by default; Bun selectable for final
   outputs (`Runtime: npm.Bun`), verified with `bun build` + run.

## Consequences

- No npm CLI anywhere; bob.lock is the only lock. `package-lock.json` is not generated.
- Phantom-dependency users (packages that import undeclared deps) fail under the strict layout
  (seen: `@fastify/cors` types import `fastify`). bob must translate "Cannot find module X" in a
  store file into the `npm.Extend` hint.
- A Node or toolchain bump does not rebuild package derivations (they use only coreutils/tar/
  gzip); it rebuilds the importer `node_modules` (wrappers) and allowed-script packages.
- Editors outside the namespace work through `.bob/bin` shims (tsserver, eslint verified), but
  go-to-definition into dependencies returns `/nix/store/…` paths, which do not exist on hosts
  without `/nix`.

## Alternatives rejected

- Running `npm ci` in a fixed-output derivation: not reproducible across npm versions, needs
  the npm CLI (D15), and one change refetches everything.
- One derivation per importer with a copied `.pnpm` virtual store: no sharing, same rebuild
  cost as hoisted.
- Hoisted as default: phantom dependencies "work", but peer resolution is wrong (decision 2)
  and incremental cost is higher.
