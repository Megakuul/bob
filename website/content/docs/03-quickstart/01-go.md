In this quickstart you build the smallest useful Go project with bob: one program with one
test. You lock, build, test, run, check the project and use its dev environment.

You need [bob installed](../02-install/02-install-bob.md). You do not need Go installed: the
toolchain comes from nixpkgs when bob first needs it.

## Start the project

```bash
mkdir hello-go && cd hello-go
git init
```

git is optional (bob finds the root of a project by its `bob.lock`); `bob check` below uses
it. Let bob write the project:

```bash run
bob init
```

```text expect
bob init: go project in …
  + bob.go
  + cmd/hello/main.go
  + cmd/hello/main_test.go
bob.lock: 2 changes
…
  + nixpkgs  nixpkgs   …
next: bob build && bob test && bob run //cmd/hello:hello
```

```tree
📁 hello-go/
  📄 bob.go
  📄 bob.lock
  🐹 go.mod
  📁 cmd/
    📁 hello/
      🐹 main.go
      🐹 main_test.go
```

`bob init` wrote the program, its test and `bob.go`, locked the project and wrote `go.mod`. It
never overwrites a file. `bob.lock` pins the revision of the `nixos-26.05` channel. Commit it
with your code. The other languages: `bob init --lang cc|rust|npm|ocaml` ([CLI reference](../05-cli/01-commands.md#bob-init)).

## The code

`cmd/hello/main.go` is a program with one function to test:

```go
package main

import "fmt"

func greeting(name string) string { return "hello, " + name }

func main() { fmt.Println(greeting("bob")) }
```

`cmd/hello/main_test.go` tests it:

```go
package main

import "testing"

func TestGreeting(t *testing.T) {
	if got := greeting("bob"); got != "hello, bob" {
		t.Fatalf("got %q", got)
	}
}
```

## The build description

`bob.go` pins nixpkgs (which decides the Go version) and declares the module, the program and
its tests. The module path is `example.com/` plus the directory name; change it here and run
`bob lock` when you publish the module:

```go verify
//go:build bob

package hellogo

import (
	"github.com/megakuul/bob/pkg/bob"
	"github.com/megakuul/bob/pkg/golang"
)

var _ = bob.Repo(bob.RepoOpts{Nixpkgs: "nixos-26.05"})

var Module = bob.Define(func(p *bob.P) *golang.Module {
	return golang.NewModule(p, golang.ModuleOpts{Path: "example.com/hello-go", Go: "1.26"})
})

var Hello = bob.Define(func(p *bob.P) *golang.Binary {
	return Module(p).Binary("./cmd/hello", golang.BinaryOpts{})
})

var Tests = bob.Define(func(p *bob.P) *golang.TestSet {
	return Module(p).Tests("./...", golang.TestOpts{})
})
```

`go.mod` is generated from `bob.go` (and `go.sum` once the module has requirements): do not
edit it. After a change to `bob.go` that adds or moves a dependency, run `bob lock`.

## Build

```bash run
bob build
```

```text expect
built   //cmd/hello:hello
…
bob: 1 built
```

Go came from `cache.nixos.org` during `bob init`. `//:module` and `//:tests` show as
`cached`: they describe, they do not compile. Build again and nothing happens:

```bash run
bob build
```

```text expect
bob: nothing to do
```

## Test and run

```bash run
bob test
```

```text expect
PASS    //cmd/hello:go_test (…s)
bob: 1 passed, 0 failed, 0 cached
```

Each Go package is one test unit. Passing results are cached until the package or a
dependency changes.

```bash run
bob run //cmd/hello:hello
```

```text expect
hello, bob
```

Arguments after `--` go to the program: `bob run //cmd/hello:hello -- --flag`.

## Look at the graph

```bash run
bob graph
```

```text expect
//:tests                        bob.go:…
└─ //cmd/hello:go_test          bob.go:…
   ├─ //:module                 bob.go:…
   │  └─ nixpkgs:go_1_26        bob.go:…
…
//cmd/hello:hello               bob.go:…
```

Every package shows where it was defined.

## Check for drift

`bob check` compares generated files and the lock with `bob.go`, without changing anything.
In a new repository it finds one problem, because git does not ignore bob's state directory
yet:

```bash run exit=3
bob check
```

```text expect
error[BOB-E-1013]: .bob/ is not ignored by git
  hint: bob check --fix adds it to bob's block in .git/info/exclude
bob: 1 problem (exit 3)
```

Exit status 3 means "a definition problem, before building". Let bob fix it; it writes to
`.git/info/exclude` and never touches your `.gitignore`:

```bash run
bob check --fix
bob check
```

```text expect
bob: no problems
bob: no problems
```

`bob init` wrote `go.mod` from `bob.go`. Edit it by hand and `bob check` reports
`BOB-E-1011` ("generated file go.mod was edited by hand").

## Use the dev environment

`bob dev` starts a shell (or runs a command) with Go and gopls of your nixpkgs pin on `PATH`.
`bob exec` runs one tool:

```bash run
bob dev -- go version
bob exec -- go version
```

```text expect
bob: dev shell default (go 1.26.8, gopls …) · …
go version go1.26.8 linux/…
go version go1.26.8 linux/…
```

bob also writes wrapper scripts to `.bob/bin` (`go`, `gofmt`, `gopls`) for your editor. See
[Dev environments](../04-guides/05-dev-environments.md).

## What to commit

`bob.go`, `bob.lock`, `go.mod` (and `go.sum` once there is one) and your code. `.bob/` is
bob's local state.
