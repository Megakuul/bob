In this quickstart you build a small Go command with bob: a module with one library package,
one test and one binary that uses a third-party module. You lock the dependencies, build,
test, run, enter the dev environment and check the project for drift.

You need [bob installed](../02-install/02-install-bob.md) and a few minutes for the first
download of the Go toolchain. You do not need Go installed.

## The project

```text
hello-go/
├── go.mod               module line (bob rewrites the rest)
├── bob.go               the module, its tests, the nixpkgs pin
├── greet/
│   ├── greet.go
│   └── greet_test.go
└── cmd/hello/
    ├── bob.go           the binary
    └── main.go
```

Create an empty directory and make it a git repository. bob uses the nearest `.git` to find
the root of a new project:

```bash
mkdir hello-go && cd hello-go
git init
```

## Write the code

`greet/greet.go`:

```go file=greet/greet.go
// Package greet builds greetings.
package greet

// Hello returns a greeting for name.
func Hello(name string) string { return "hello, " + name }
```

`greet/greet_test.go`:

```go file=greet/greet_test.go
package greet

import "testing"

func TestHello(t *testing.T) {
	if got := Hello("bob"); got != "hello, bob" {
		t.Fatalf("Hello(bob) = %q", got)
	}
}
```

`cmd/hello/main.go` uses the `github.com/google/uuid` module:

```go file=cmd/hello/main.go
// Command hello prints a greeting and a fresh request id.
package main

import (
	"fmt"
	"os"

	"example.com/hello/greet"
	"github.com/google/uuid"
)

func main() {
	name := "world"
	if len(os.Args) > 1 {
		name = os.Args[1]
	}
	fmt.Println(greet.Hello(name), uuid.NewString())
}
```

## Describe the build

The root `bob.go` pins nixpkgs (which decides the Go version) and declares the module. Its
requirements replace the `require` lines you would write in `go.mod`:

```go file=bob.go
//go:build bob

package hello

import (
	"github.com/megakuul/bob/pkg/bob"
	"github.com/megakuul/bob/pkg/golang"
)

// Pin the nixpkgs channel that provides the Go toolchain.
var _ = bob.Repo(bob.RepoOpts{Nixpkgs: "nixos-26.05"})

// Module is the Go module example.com/hello (label //:module).
var Module = bob.Define(func(p *bob.P) *golang.Module {
	return golang.NewModule(p, golang.ModuleOpts{
		Path:    "example.com/hello",
		Go:      "1.26",
		Require: []golang.Requirement{golang.Require("github.com/google/uuid", "v1.6.0")},
	})
})

// Tests runs one test unit per package of the module.
var Tests = bob.Define(func(p *bob.P) *golang.TestSet {
	return Module(p).Tests("./...", golang.TestOpts{})
})
```

`cmd/hello/bob.go` declares the binary. It is in a `main` package directory, so its package
clause is `main` too. It imports the root `bob.go` by the module path:

```go file=cmd/hello/bob.go
//go:build bob

package main

import (
	"example.com/hello"
	"github.com/megakuul/bob/pkg/bob"
	"github.com/megakuul/bob/pkg/golang"
)

// Binary is the hello command (label //cmd/hello:hello).
var Binary = bob.Define(func(p *bob.P) *golang.Binary {
	return hello.Module(p).Binary("./cmd/hello", golang.BinaryOpts{})
})
```

Finally, create a `go.mod` with only the module line and the Go version. bob needs it to
compile the `bob.go` files, and rewrites it from `bob.go` on the first build:

```text file=go.mod
module example.com/hello

go 1.26.0
```

> [!WARNING]
> Today you have to create this first `go.mod` by hand, in every bob repository (also for
> C/C++, Rust, TypeScript and OCaml projects). Without it, bob stops with
> `BOB-E-9005 … the repository has no go.mod`. Write the Go version with three parts
> (`1.26.0`); `go 1.26` is reported as a hand edit (`BOB-E-1011`) until you run
> `bob gen --force`.

## Lock the dependencies

```bash run
bob lock
```

```text expect
bob.lock: 2 changes
  + go       github.com/google/uuid   v1.6.0
  + nixpkgs  nixpkgs                  …
```

`bob.lock` now pins the nixpkgs revision of the `nixos-26.05` channel and the uuid module
with its hashes. Commit it together with your code.

## Build

```bash run
bob build
```

```text expect
built   //cmd/hello:hello
…
bob: 1 built
```

The first build downloads the Go toolchain from `cache.nixos.org`; later builds reuse it.
The other packages (`//:module`, `//:tests`) are listed as `cached`: they are descriptions,
not compiled code. Build again, and nothing happens:

```bash run
bob build
```

```text expect
bob: nothing to do
```

bob also rewrote `go.mod` and wrote `go.sum`, so `gopls` and `go list` see the same module
graph as the build:

```bash run
cat go.mod
```

```text expect
// Code generated by bob from bob.go. DO NOT EDIT.
// Edit bob.go and run bob lock.
module example.com/hello
go 1.26.0
require (
	github.com/google/uuid v1.6.0
)
```

## Test

```bash run
bob test
```

```text expect
PASS    //greet:go_test (…s)
bob: 1 passed, 0 failed, 0 cached
```

Each Go package is one test unit (`//greet:go_test`). A passing result is cached: run
`bob test` again and it reports `cached` until the package or a dependency changes. A
failing test runs again every time.

## Run

`bob run` builds the binary for this machine and runs it. Arguments after `--` go to the
program:

```bash run
bob run //cmd/hello:hello -- bob
```

```text expect
hello, bob …-…-…-…-…
```

## Look at the graph

```bash run
bob graph
```

```text expect
//:tests                        bob.go:…
└─ //greet:go_test              bob.go:…
   ├─ //:module                 bob.go:…
   │  └─ nixpkgs:go_1_26        bob.go:…
…
//cmd/hello:hello               cmd/hello/bob.go:…
```

Each line shows a package and where it was defined. `bob graph --why //cmd/hello:hello
nixpkgs:go_1_26` prints the dependency path between two packages; `--format json` and
`--format dot` print machine-readable graphs.

## Check for drift

`bob check` compares the generated files with what bob would write, and the lock with
`bob.go`, without changing anything. In a new repository it finds one problem: git does not
ignore bob's state directory yet.

```bash run exit=3
bob check
```

```text expect
error[BOB-E-1013]: .bob/ is not ignored by git
  hint: bob check --fix adds it to bob's block in .git/info/exclude
bob: 1 problem (exit 3)
```

Exit status 3 means "a definition problem, before building". Let bob fix it. bob writes a
marked block to `.git/info/exclude` and never touches your `.gitignore`:

```bash run
bob check --fix
bob check
```

```text expect
bob: no problems
bob: no problems
```

Try a hand edit: add a line to `go.mod` and run `bob check` again. bob reports
`BOB-E-1011: generated file go.mod was edited by hand`. `bob check --fix` rewrites the file.

## Use the dev environment

`bob dev` starts a shell (or runs a command) with the project's toolchains on `PATH`: here Go
and gopls at the versions of your nixpkgs pin.

```bash run
bob dev -- sh -c 'go version'
```

```text expect
bob: dev shell default (go 1.26.8, gopls …) · …
go version go1.26.8 linux/…
```

`bob dev` without `--` starts your `$SHELL`. For one tool, `bob exec` is shorter:

```bash run
bob exec -- go version
```

```text expect
go version go1.26.8 linux/…
```

> [!WARNING]
> `bob dev -- go version` (a toolchain command directly after `--`) fails with
> `BOB-E-0005: go is not runnable`. Wrap the command in a shell, as above, or use `bob exec`.

bob also writes small wrapper scripts to `.bob/bin` (`go`, `gofmt`, `gopls`), so editors can
run the toolchain without entering `bob dev`. See
[Dev environments](../04-guides/05-dev-environments.md).

## Change something

Edit `greet/greet.go`:

```go file=greet/greet.go
// Package greet builds greetings.
package greet

// Hello returns a greeting for name.
func Hello(name string) string { return "hello, " + name + "!" }
```

Run the tests again. The test unit of `greet` runs again and fails, because the expected
text did not change:

```bash run exit=1
bob test
```

```text expect
FAIL    //greet:go_test (…s)
error[BOB-E-2005]: //greet:go_test: tests failed
…
  hint: run bob test //greet:go_test -v to see the full test output
…
bob: 0 passed, 1 failed, 0 cached (exit 1)
```

The exit status is 1: your code failed. Exit statuses tell you who has to act; see
[Exit codes](../05-cli/01-commands.md#exit-codes). Put the old line back to make the test pass
again.

## What you have now

- `bob.go` files that describe the module, its tests and the binary in typed Go;
- `bob.lock`, which pins nixpkgs and the uuid module;
- a generated `go.mod`/`go.sum` for your editor;
- `.bob/`, bob's local state, ignored through `.git/info/exclude`.

Commit `bob.go`, `cmd/hello/bob.go`, `bob.lock`, `go.mod`, `go.sum` and your code.
